# v2.3.1

## Changes

- Unify decision-relevant claims around four evidence states: verified, inference, unknown, and refuted. Optional acquired-basis attributes distinguish source inspection, specifications, and runtime observations without treating them as confidence scores.
- Keep natural prose for conversation and exploration. Add explicit evidence, scope, and unresolved premises near claims used for recommendations, changes, acceptance, or handoff; examples are not mandatory report templates.
- Align plan, debug, CI diagnosis, and insight output with the shared rules. Preserve factual uncertainty through plan re-entry and keep user choices separate from technical verification.
- Deploy communication and reasoning rules through the normal installer. Short bilingual reminders point to the shared semantics rather than duplicating the policy.
- Stop globally rewriting requested filenames, paths, and shell environment setup. Project conventions and explicit instructions determine those choices.
- Automatically approve Markdown plan edits only under the user plan directory and the current workspace's `plans/` directory. Other files and shell commands gain no permission from that rule.

- Pin the direct insight test dependencies and run an isolated release-binary installation check in both Linux and Windows CI.
- Correct the managed-UI test to compare against the actual Python worker PID, including Windows virtual-environment launchers, while retaining the stdin-EOF shutdown check.

## Migration and compatibility

**Insight JSON producers and consumers need attention.** New findings require `evidence_state` and optionally accept `evidence_basis`; the new finding schemas reject the retired numeric cognitive `confidence` field. The renderer can still read older findings JSON, but displays old scores as legacy records that have not been reassessed under the new evidence contract. This is old-input rendering compatibility, not validation or write compatibility with the new schemas. Update custom finding producers, validators, and consumers together; do not mix old angle templates with new schemas.

Packet evidence `status` and 0–1 `confidence`, security scoring, and adversarial-review verdicts keep their existing meanings. An adversarial vote does not establish a fact or automatically promote its evidence state.

Use the normal binary upgrade/install path to deploy `style.md` and both `rules/` files together, then start a new session to load the updated instructions. Copying `style.md` alone does not deploy the independent rules. The installer preserves ownership checks and reports conflicts with customized managed files or same-name user rules; do not discard a manifest or overwrite user configuration to bypass them.

This release does not include the separate insight vote-threshold or agent-budget scheduling changes. Static prompt tests and renderer tests do not establish improved model compliance, hallucination rates, or long-context behavior.
