# v2.3.2

## Changes

- Separate composable task attributes from evidence states. Plan changes from goals, hard constraints, responsibility boundaries and applicable contracts rather than a binary implementation/architecture grade.
- Preserve remy-plan's seven phases, five-category scan, five audit tables, visible confirmation checkpoints and existing re-entry budgets. Add bidirectional coverage from goals, preserved contracts and selected scenario branches to acceptance checks and handoff text.
- Keep remy-patch recovery material and behavior-decision records, check concurrent changes before recovery, and handle scope, stale evidence and requirement conflicts separately. Collect planned manual, compatibility and recovery checks instead of substituting symbol-related tests alone.
- Distinguish characterization from conformance in remy-testgen. Carry requirement sources and preservation boundaries into its three generation prompts; distinguish missing-behavior RED from test or environment failures, and retain passing regressions.
- Extend prompt-contract, fixture, embedded-resource and isolated-install checks. Retain the daemon test startup-deadline and failure-diagnostic improvements merged after v2.3.1.

## Migration and compatibility

The five audit JSON groups and the AgentTaskPacketLite envelope remain unchanged. Existing evidence `status` and `confidence` fields retain their meanings. Historical `grade` input remains readable but no longer drives recommendations or new audit output; `scope_position` remains a string. No new planning-contract validator or packet migration is required.

The task attributes are not authorization. Reading a consumer does not authorize modifying it, and a generated plan does not establish that checks ran or passed. Unsupported version/data combinations need not become supported; required rejection or isolation behavior must still be checked.

Use the normal binary update/install path, then start a new Claude Code session to load the updated rules and skills. Customized managed files remain subject to installer ownership/conflict checks; do not remove the manifest or overwrite user configuration to bypass them. Restarting the daemon does not reload instructions or every existing MCP process in an already-open session.

## Validation scope

Local Windows checks passed for 107 targeted Python tests, type checking, 10 embedded-resource tests, 24 installer tests and an isolated release-binary installation. These checks do not establish universal model compliance.

The earlier 24-answer planning trial retains its partial result. In a separate, frozen Phase 5–6 text replay, the Chinese subset met the criteria in 4/4 candidate conditions; its pre-supplement comparison met 3/4, with one partial result. The English conditions received a conflicting Chinese session-language directive, so the bilingual batch was not completed. This is not a full seven-phase execution test or evidence of general superiority. See [the preserved experiment record](../PROMPT_BEHAVIOR_CASES.md) for methods, limitations and unrepeated samples.
