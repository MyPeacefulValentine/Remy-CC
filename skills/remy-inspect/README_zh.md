# remy-inspect（修改后验证）

remy-inspect 发现已有测试、为未覆盖代码创建临时测试、运行测试、评估分支覆盖率并审计断言质量。它在代码修改之后运行——与 TDD（实现之前运行）互补。

支持通过并行 Agent 进行多角度缺陷预判和语义级测试质量审计，设计灵感来自 `/code-review` 的多视角审查模式。

## 何时使用

- `/remy-patch` 之后、生成变更日志之前
- 验证代码变更是否被测试覆盖
- 评估被修改函数的测试质量

## 用法

```
/remy-inspect [effort] [目标文件或函数...]
```

### 努力级别

| 级别 | 预判角度 | 审计角度 | Agent 数 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `low` | 0 | 0（仅 regex） | 0 | 快速模式，不启动 Agent。兼容 v2 之前行为。 |
| `medium`（默认） | 2 | 1 | 3 | 输入边界 + 错误路径预判；覆盖差距审计。 |
| `high` | 3 | 3 | 6 | 增加状态/交互预判；断言强度 + 测试隔离审计。 |

## 工作流

### Phase 1: 范围识别

通过 `git diff` 或用户指定的目标确定变更内容。构建包含修改/新增的函数、类和方法的变更集。

### Phase 2: 测试发现

加载 `frameworks.json` 中的检测规则，识别项目的测试框架（pytest、jest、go test 等）。通过 grep 将每个变更符号映射到已有的测试文件。

### Phase 2.5: 缺陷预判（medium/high）

并行启动多个 Agent，从不同视角独立分析变更代码：

- **角度 A — 输入边界**：识别可能触发错误行为的边界输入（null、空值、溢出、类型混淆）。
- **角度 B — 错误路径**：识别未被显式测试的异常处理器、fallback 逻辑和 I/O 失败路径。
- **角度 C — 状态/交互**（仅 high）：识别并发风险、隐式前置条件和部分失败场景。

每个 Agent 输出最多 6 个结构化失败场景。结果合并、去重并按优先级排序。场景列表驱动 Phase 3 的针对性测试生成。

### Phase 3: 测试创建（条件执行）

对无已有测试覆盖的符号——或 Phase 2.5 产出了场景——生成临时测试。当场景可用时，测试针对预判结果中的具体失败条件和触发输入。

测试要求：每个行为一个断言、仅测试公共接口、确定性、非外部 I/O 不使用 mock。

### Phase 4: 执行与修复循环

运行测试并对失败进行分类。分类决策树在尝试修复前，先判定失败属于测试缺陷还是实现缺陷。追踪预判准确率：多少预判场景被实际测试失败所证实。

### Phase 5: 覆盖率评估

测量变更函数的分支覆盖率（通过覆盖率工具或静态分析）。阈值：≥ 80%。低于阈值的符号触发额外测试创建。

### Phase 6: 质量审计（双层）

**Layer 1 — Regex 反模式**（始终执行）：使用 `anti_patterns.json` 中定义的规则扫描测试文件（恒真断言、仅 mock 测试等）。

**Layer 2 — 语义审计**（medium/high）：并行 Agent 评估测试质量：

- **角度 A — 覆盖-行为差距**：检测测试通过但未验证关键条件的情况（名称-断言不匹配、仅类型检查、副作用盲区）。
- **角度 B — 断言强度**（仅 high）：检测过弱断言导致假阳性通过。
- **角度 C — 测试隔离**（仅 high）：检测测试间隐式依赖导致非确定性失败。

两层结果合并去重。Critical 级别发现阻塞通过。

### Phase 7: 清理

删除 Phase 3 中创建的全部临时测试文件。

### Phase 8: 报告

将结构化报告保存到 `.claude/temp_test/report_{timestamp}.md`，包含预判准确率指标、语义审计发现，以及标准的覆盖率/结果摘要。

## 配置

| 变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `POST_VERIFY_MAX_RETRIES` | `-1`（无限制） | 测试-修复最大迭代次数。`-1` = 无限制。 |
| `POST_VERIFY_EFFORT` | `medium` | 未通过参数指定时的回退努力级别。 |

## 文件结构

| 文件 / 目录 | 用途 |
| :--- | :--- |
| `SKILL.md` | 完整协议定义（由 Claude Code 加载） |
| `frameworks.json` | 测试框架检测规则（用户可扩展） |
| `anti_patterns.json` | 断言反模式规则（用户可扩展） |
| `prompts/` | 预判和审计角度的 Agent 提示词模板 |
| `schemas/` | 定义 Agent 输出格式的 JSON schema |
| `templates/` | 临时测试生成和报告的 Jinja2 模板 |
| `render.py` | 模板渲染工具（Jinja2 + 回退） |
