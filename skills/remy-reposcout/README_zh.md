# remy-reposcout（仓库检查）

remy-reposcout 在沙盒临时目录中检查 GitHub 仓库。它分两阶段运行，避免对大型仓库进行不必要的克隆。

## 何时使用

- 集成或引用一个不熟悉的仓库前，评估其结构和规模
- 分析仓库的目录结构、技术栈和大小，不污染工作区

## 工作流

### 阶段 1: 侦察

1. 验证 GitHub URL。
2. 通过 `gh repo view` 获取仓库元数据（描述、Star 数、磁盘占用、默认分支）。
3. 通过 `gh api` 获取并显示完整的 README 内容。
4. 输出摘要报告。磁盘占用超过 500 MB 时发出警告。
5. 询问用户是否继续进行完整克隆。

### 阶段 2: 深度检查

仅在用户确认后执行。

1. 运行 `audit_runner.py`，将仓库克隆到临时目录，执行二次大小检查（500 MB 安全限制，`--force` 可覆盖），并生成结构报告。
2. 分析文件树和技术栈。
3. 使用标准工具（Glob、Grep、Read）在临时目录中探索文件。
4. 检查完成后删除临时目录。

## 环境要求

- `git`
- `gh`（GitHub CLI），需通过 `gh auth login` 完成认证

## 相关文件

| 文件 | 用途 |
| :--- | :--- |
| `SKILL.md` | 完整协议定义（由 Claude Code 加载） |
| `scripts/audit_runner.py` | 克隆、大小检查和结构分析脚本 |

## 后续步骤

`/remy-reposcout` 完成浅层评估后，用户将仓库 clone 到本地，可使用 `/remy-insight` 进行多智能体深度分析（需先运行 `/init` + `/remy-index`）。
