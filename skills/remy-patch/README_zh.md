# remy-patch（工程化代码修改）

remy-patch 通过依赖追踪、框架完整性检查和增量变更约束来执行代码修改。它以"隔离上下文"方式运行——AI 独立发现调用链和依赖关系，而非依赖对话记忆。

## 何时使用

- `/remy-plan` 审批后，执行有边界约束的计划变更
- 修改、重构或优化现有代码
- 存在来自 `/remy-plan` 的任务包时（可选，复杂变更推荐使用）

## 工作流

### Phase 0: 任务包加载（条件执行）

如果提供了 `task_packet_file` 参数，Skill 读取 `.claude/temp_task/{task_packet_file}`，以 `proposed_changes[]` 作为权威变更范围。禁止超出该范围的修改。未提供任务包时，进入自由发现模式。

### Phase 1: 依赖发现

1. 检查 `.claude/logic_index.db` 是否存在。存在时对目标文件运行 `impact.py`，生成双向依赖报告（上游调用者和下游被调用者）。
2. 逻辑索引不可用时，回退到基于 grep/glob 的手动追踪。
3. 读取上游深度 1 和下游深度 1 的全部文件。
4. 验证待使用的外部函数签名。

### Phase 2: 框架合规检查

检查目标文件中是否存在对语言/特性有约束的编译器装饰器或元编程模式。若检测到，验证新代码与其兼容。未检测到时跳过。

### Phase 3: 执行

对每个待修改文件：

1. **预读取与缓存** — 读取文件并缓存原始内容，用于可能的回滚。
2. **发现检查点**（仅 packet 模式） — 每次 Edit 调用前检查 3 个条件：
   - H1: 文件不在 `proposed_changes[]` 中（范围溢出）
   - H2: 目标函数签名自审计以来已变化（计划过期）
   - H3: 编辑将违反 `sender_payload.analysis` 中的约束（约束冲突）

   任一条件为真时触发**硬中断**：AI 暂停并向用户提供选项——扩展范围、中止并回滚、或忽略并继续。
3. **编辑与验证** — 应用修改并通过后读取验证。
4. **软决策日志**（仅 packet 模式） — 未被 packet 覆盖的行为选择记录到 `.claude/temp_decisions/decisions_{PACKET_ID}.md`。若无未覆盖的决策则不创建文件。

### Phase 4: 验证

运行相关测试。失败时提供修复、回滚或忽略选项。

## 流水线集成

此 Skill 是 计划 → 修改 → 审计 流水线的第二阶段：

```
/remy-plan → 任务包 → /remy-patch → /remy-audit
```

有任务包时，Skill 执行严格的变更边界约束。无任务包时，无约束运行。
