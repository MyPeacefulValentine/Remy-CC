# Deep Plan（架构预审）

Deep Plan 是一个零代码架构审计协议。它要求 AI 在编写任何实现代码之前，完成歧义消除、不变量定义和逻辑推演。核心原则：**先决策，后编码。**

## 何时使用

- 修改核心逻辑或共享组件的复杂重构
- 需求不明确或存在多条实现路径的新功能开发
- 数据迁移、权限变更或不可逆操作等高风险场景

## 工作流

### Phase 1: 上下文加载

AI 首先检查 `.claude/logic_index.json` 是否存在：

- **存在**：对目标文件运行 `impact.py`，生成双向影响报告——上游（谁调用了此代码）和下游（此代码调用了谁），包含跨层警告。强制读取上游深度 1 和下游深度 1 的全部文件。跨层影响标记后进入 Table 3 审计。
- **不存在**：提示用户运行 `/update-logic-index`，或回退到基于 grep/glob 的手动探索。

两条路径下，AI 均必须读取所有相关源码定义。禁止基于不完整信息进行规划。

还会执行**复用扫描**：对任何计划新建的函数或工具，搜索项目中是否已存在类似实现。若存在可复用函数，计划必须引用已有实现而非提议新代码。

### Phase 2: 交互式歧义消除（循环）

AI 使用强制 5 类清单（接口契约、资源依赖、行为边界、执行顺序、变更边界）扫描歧义。如果存在多条技术路径，AI **必须**暂停并通过 `AskUserQuestion` 向用户提问——每个问题必须包含 1 个推荐选项及 1 句理由。存在依赖关系的问题按顺序逐个呈现，不批量提出。

收到回答后，AI 搜索相关代码并对所有已锁定决策执行**交叉约束验证**。若发现矛盾，将冲突的先前决策标记为无效并重新提问。此循环重复直到所有"待定"项转为"已锁定"约束。

### Phase 2.8: 假设清单与场景探测

循环退出后，AI 生成一份包含所有隐含假设（实现级和行为级）的清单，不包含 Table 1 中已有的条目。每项假设包含置信度和类别。置信度 ≤ Level 4 的假设触发场景探测——AI 构造一个具体执行场景，帮助用户判断假设是否正确。

假设通过 `AskUserQuestion` 分批呈现。用户否决时触发一次性回退到 Step 2 循环以解决新歧义。禁止第二次回退。

### Phase 2.9: 计划-代码对齐检查

生成最终表格前，AI 重新读取目标函数签名，确认无并发外部修改使计划假设失效。若检测到矛盾，重新进入歧义消除循环。

### Phase 3: 五表审计

歧义消除后，AI 加载 `audit_template.md` 中的报告模板，生成五张表：

| 表格 | 用途 |
| :--- | :--- |
| 歧义消除矩阵 | 记录所有决策点及其锁定方案。任何未锁定的歧义将拒绝计划。 |
| PBT 属性规约 | 定义数学不变量（幂等性、可逆性等），指导测试用例设计。 |
| 逻辑与契约审计 | 检查数据流一致性、复杂度（Big-O）、并发风险和系统副作用。 |
| 物理变更预演 | 列出每个待修改的文件、函数和操作类型，附带涟漪效应估算。 |
| 验证计划 | 定义实现完成后的端到端验证方法及回退条件。 |

### Phase 4: 任务包生成

五表生成后，AI 将 `AgentTaskPacketLite` JSON 文件写入 `.claude/temp_task/task_{TIMESTAMP}.json`。包含：

- **证据链**：审计过程中读取的每个文件的原文摘录。
- **变更提案**：映射到证据引用的文件级操作。
- **Git 版本**：Commit Hash 和时间戳。

同时更新 `.active_packet` 指针指向新任务包。

### Phase 5: 强制停止

AI 停止并给出三个选项：

> 审计完成。[继续执行] / [修改计划] / [取消]？

此阶段不产生任何代码。

## 计划-修改-审计 流水线

Deep Plan 是三 Skill 流水线的第一阶段：

```
/deep-plan
  └─→ 写入 .claude/temp_task/task_{TIMESTAMP}.json
         └─→ /code-modification task_{TIMESTAMP}.json
               （以 proposed_changes[] 作为变更约束）
                      └─→ /auditor [日志文件] task_{TIMESTAMP}.json
                            （三方校验：计划 vs. 变更日志 vs. 代码）
```

跳过 `/deep-plan` 意味着 `/code-modification` 无边界约束运行，`/auditor` 退化为两方校验。

## 禁止事项

- **禁止生成代码**：此阶段严禁生成或修改任何实现代码。
- **禁止假设**：AI 不得假设用户意图，必须通过提问确认。
