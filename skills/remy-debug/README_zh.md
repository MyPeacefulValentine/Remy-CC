# remy-debug（Bug 诊断）

remy-debug 通过结构化假设循环与熔断器追踪 Bug 根因。它生成诊断报告和与 `/remy-patch` 兼容的证据包，不修改源代码。

## 何时使用

- 测试失败且原因不明
- 日志或运行时输出中出现错误
- 近期修改后引入了回归问题

## 工作流

### Phase 0: 症状捕获

从参数、测试输出或引导式提问中收集可观察的错误信息。

### Phase 1: 定位

解析栈追踪或以错误关键字 grep 定位可疑文件。可选调用逻辑索引影响分析、收集 git 历史用于回归范围界定，最后读取可疑代码。

### Phase 2: 假设循环

1. 使用共享证据状态形成假设；需要区分已有依据时附加属性，如 `[~｜源码]`。
2. 选择允许的只读查证或既有测试；测试执行须符合当前授权和模式，不因此允许创建临时脚本。
3. 分别记录观察结果、检查范围和未核实的因果前提。
4. 确认、反驳或保留无结论假设；流程 verdict 与证据标记分别保留。
5. 在有界机制被核实、熔断器触发（`DEBUG_MAX_HYPOTHESES`，默认：3）、访问或授权受阻、继续尝试不再增加证据时停止。后几类保留无结论诊断。

### Phase 3: 诊断报告

输出结构化报告到 `.claude/temp_debug/debug_{timestamp}.md`，包含：
- 症状描述
- 假设链及证据
- 根因结论
- 修复建议（不执行修改）

### Phase 4: 证据包

生成 `.claude/temp_task/task_*.json` 包，供 `/remy-patch` 执行修复。

### Phase 5: 强制停止

诊断报告与证据包写入后，打印诊断摘要与后续命令（`/remy-patch debug_{TIMESTAMP}.json`，仅当 mode = "write" 时），随后停止。不执行任何代码修改。

## 配置

| 环境变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `DEBUG_MAX_HYPOTHESES` | `3` | 熔断器触发前的最大假设迭代次数。 |

## 参数

```
/remy-debug [错误描述 | 测试命令 | 文件:行号] [--since <ref>]
```

- 无参数：进入引导模式（交互式症状收集）
- 测试文件模式（`test_*.py`）：视为测试命令
- `文件:行号` 模式：视为位置引用
- 其他文本：视为错误描述
- `--since <ref>`：将回归分析范围限定为给定 git ref 之后的变更
