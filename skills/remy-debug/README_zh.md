# remy-debug（Bug 诊断）

remy-debug 通过结构化假设循环与熔断器追踪 Bug 根因。它生成诊断报告和与 `/remy-patch` 兼容的证据包，不修改源代码。

## 何时使用

- 测试失败且原因不明
- 日志或运行时输出中出现错误
- 近期修改后引入了回归问题

## 工作流

### Phase 0: 症状捕获

从参数、测试输出或引导式提问中收集可观察的错误信息。

### Phase 1: 上下文饱和

通过逻辑索引影响分析（如可用）或手动 grep 追踪读取故障代码路径。

### Phase 2: 假设循环

1. 根据证据形成假设
2. 设计非侵入式探针（只读 Bash、grep、定向 Read）
3. 执行探针并记录结果
4. 确认或否定假设
5. 重复直到识别根因或熔断器触发（`DEBUG_MAX_HYPOTHESES`，默认：3）

### Phase 3: 诊断报告

输出结构化报告，包含：
- 症状描述
- 假设链及证据
- 根因结论
- 修复建议（不执行修改）

### Phase 4: 证据包

生成 `.claude/temp_task/task_*.json` 包，供 `/remy-patch` 执行修复。

## 配置

| 环境变量 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `DEBUG_MAX_HYPOTHESES` | `3` | 熔断器触发前的最大假设迭代次数。 |

## 参数

```
/remy-debug [错误描述 | 测试命令 | 文件:行号] [--since <ref>]
```

- 无参数：进入引导模式（交互式症状收集）
- 测试文件模式（`test_*.py`）：视为测试命令
- `文件:行号` 模式：视为位置引用
- 其他文本：视为错误描述
- `--since <ref>`：将回归分析范围限定为给定 git ref 之后的变更
